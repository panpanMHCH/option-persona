# Benchmark of existing tools

**Source note:** this benchmark is based on my existing knowledge of these tools (training data up to mid-2026). It was **not** re-verified against live websites or documentation for this write-up. Pricing tiers and features change often, so check the details before relying on them.

| Tool | What it is | Strengths | What it does not do (for our purposes) |
|---|---|---|---|
| **OptionStrat** | Web strategy builder and visualiser; also offers an options-flow product | Fast multi-leg payoff and P&L-through-time charts, strategy optimiser, polished UX | Closed models with limited exposure of assumptions; no arbitrage-feasibility research; P&L curves typically use a single IV assumption |
| **ORATS** | Institutional options data and analytics vendor | Cleaned historical chains, smoothed volatility surfaces, earnings-adjusted IV, backtester, data API | Paid; its value is the *data*, which we should not try to recreate; a black box from a learning perspective |
| **QuantConnect / LEAN** | Open-source (Apache-2.0) algorithmic trading engine in C#/Python, plus a cloud platform | Event-driven backtesting and live trading; options universe selection; uses QuantLib-based pricing models | A general trading engine, not an explainable research workflow; historical options data is via its paid cloud; it is built for automated execution, which is out of scope here |
| **Interactive Brokers** (Option Analytics, Risk Navigator, Probability Lab) | Broker-integrated analytics | Real-time Greeks, portfolio-level what-if risk, IV surfaces on live data | Proprietary models; tied to an account; not reproducible or auditable; Probability Lab "probabilities" mix risk-neutral and user views |
| **py_vollib / py_vollib_vectorized** | Python Black, Black-Scholes and BSM pricing, Greeks and IV | Uses Jäckel's *Let's Be Rational* for machine-precision IV; vectorised variant | European only; no data model, provenance, arbitrage or risk layer |
| **QuantLib** (C++ with Python bindings) | Comprehensive quantitative finance library | American engines (binomial, finite differences, Barone-Adesi-Whaley), Heston, term structures, calendars and day counts | Steep learning curve and verbose API; a library, not a research workflow |
| **Open-source parity / arbitrage scanners** (assorted GitHub projects) | Scripts that flag put-call parity or box-spread violations | Illustrate the idea | Typically use mids or last trades, ignore fees, financing, dividends, stale quotes and American exercise, so they report "arbitrage" that is not executable |

## What is commoditised (do not rebuild for its own sake)

- Payoff diagrams and P&L-through-time charts for standard strategies.
- European BSM prices and Greeks, and basic IV calculators.
- Historical options data, cleaned volatility surfaces and earnings adjustments (buy or borrow these, don't build them).
- Event-driven backtesting and execution engines (LEAN).
- Broker-side real-time risk.

## Worth implementing independently

**For learning, validated against QuantLib:**

- BSM, Greeks and IV from first principles, including degenerate limits and numerical conditioning (done in Phase 1).
- A binomial American pricer, with a convergence study and the early-exercise boundary (Phase 3).

**For differentiation (the OP thesis):**

1. **Arbitrage feasibility, not arbitrage detection.** A three-tier output: theoretical residual → apparent executable edge at bid/ask after fees and asymmetric financing → explicit execution and settlement risks. Most scanners stop at tier 1.
2. **Explainable valuation.** Every model output carries its assumptions. Observations, model values and assumptions are visibly separated, and risk-neutral and real-world probabilities are labelled.
3. **Personal risk intelligence.** Leverage and elasticity framed honestly, comparison with shares, warnings calibrated to the user's own equity, and a journal with provenance so post-trade analysis uses recorded data, not reconstructions.
4. **Reproducible verification.** Published reference values, an independent oracle, finite differences, PDE residuals and property-based tests, all regenerated by a script.

## Use rather than recreate

- **QuantLib** as a test oracle (in use) and potentially for advanced engines later.
- A data vendor or broker export for real chains in Phase 2, after a cost review.
